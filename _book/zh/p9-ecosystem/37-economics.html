第九部分 · 生态与经济 · 第 37 章

AI 的经济学

整个技术栈说穿了就是一种花钱的方式，而这笔账有它的形状。本章要讲的是算力怎么买、为什么训练和推理是两种根本不同的成本、什么时候该自建模型、什么时候该用 API，以及为什么「推理主导全生命周期账单」这个观点会反过来制约 第 3 章 里的架构和扩展决策。

发票有它的形状

前几章的每一个决策，最终都归结为发票上的某个数字。参数量变成了一笔训练账单，注意力变体变成了 KV 缓存、按小时租的内存，采样预算变成了服务账本的一列。本章要回答的，是读者一直能感受到却叫不出名字的问题：既然算力是稀缺品，它怎么定价、这笔钱怎么在自建和运行之间分配、这个分配又怎么反过来决定你该自建什么。

这道题之所以难，在于三个约束。一是算力在波动的市场上租赁，一次 FLOP 的成本不是个常数，而是不断移动的靶子。二是训练一次性花钱，推理却要永永远远花，两笔成本的时间表完全错开。三是最便宜的答案往往是从别人那儿买能力，这就意味着自建得去和一个你掌控不了、还在下跌的市场价格竞争。所以这张发票的形状，是由两套运行在不同时钟上的成本结构、由它们之间张开的那把剪刀、以及决定你落在市场哪一侧的盈亏平衡点共同决定的。

两种成本结构，两个时钟

最根本的事实是：一个 AI 系统不是一种成本结构，而是两种，而且差异大到你要是混在一块儿，决策就会彻底走偏。

训练是资本性支出。体量大、一次性、在获得任何回报之前就花了：占着集群几周，花一笔固定的钱，换来一组权重。这笔钱主要花在最后那一次实际训练，加上前面摸索配方时的各种研究和消融实验。按 Epoch AI 看 45 个前沿模型的分析，从 2016 年起最终训练的摊销硬件和能源成本每年增长约 2.4 倍，硬件是最大头，研发人员占了差不多的比例，能源是个小尾巴 (Cottier et al. 2024)。这些数字已经过时，只能看大方向：GPT-4 大约 4000 万美元，Gemini Ultra 大约 3000 万美元，按这个趋势 2027 年前后最大规模的训练就要上十亿美元 (Cottier et al. 2024)。

推理是运营性支出。单次请求成本低廉，模型每调一次就付一次钱，所以成本跟着用量走，不跟训练预算走。算推理单位成本最实用的一阶近似是：

cost per token≈accelerator $/hourthroughput (tokens/hour)×utilization\text{cost per token} \approx \frac{\text{accelerator } \$/\text{hour}} {\text{throughput (tokens/hour)} \times \text{utilization}} cost per token≈throughput (tokens/hour)×utilizationaccelerator $/hour​

这揭示了推理成本的三个杠杆：加速器租赁价格、服务栈能从硬件榨出多少吞吐量、硬件利用率有多高。第六部分的每一章都在往分母下手：第 17 章 通过批处理提高利用率，第 18 章 和 第 19 章 提高吞吐量，第 7 章 的注意力变体则缩小单个词元的计算量。

算力市场决定分子。加速器在各大云厂商和专业 GPU 云上按小时租，分三个档位：预留容量最便宜、要承诺期，按需贵一些、灵活性强，spot 最便宜、随时可能被踢下来。到 2025 和 2026 年，H100 按需价格是每 GPU 小时低个位数美元，spot 便宜得多，这是 2025 年各厂商大降价的结果，供应紧张缓和了。具体报价不重要，方向才重要：FLOP 的价格持续下跌，去年的成本假设明年就会贬值，而且会复利贬。

剪刀：训练上升，推理下降

两个时钟不只走得快慢不同，方向还相反。它们张开的缝隙是本章最关键的经济转变：自建还是购买的默认答案在这个领域已经彻底反转。

早期能力只在少数几家实验室，自建是唯一的路，买不到。后来托管 API 成熟了，买才成为可能，接着第二条曲线接管了局面：推理词元的价格每年崩落一个数量级多。2023 年 GPT-4 上线时每百万词元几十块钱，几年后同等质量只需几毛钱。开放权重大模型相继问世，DeepSeek-V3 之类的，给每家闭源厂商都丢出了个低价标杆，加速了这个过程，整个市场持续公开降价 (DeepSeek-AI 2024)。

两条曲线放在一起就一清二楚。训练成本在前沿每年涨 2.4 倍左右 (Cottier et al. 2024)，API 推理价格每年跌约一个数量级。这条不断张开的缝，就是为什么自建转向购买成了新的默认。从头自建前沿模型得去和一个持续崩塌的市场价格竞争，所以自建只在四种情况值得：保密数据无法离开边界、API 达不到的延迟或可用性指标、托管方不肯做的定制，或者推理量大到自建的成本比 API 的单价更低。

自建的成本账也改了。DeepSeek-V3，6710 亿参数的混合专家，报告最后一次训练用了约 278.8 万 H800 GPU 小时，按每小时 2 块钱算约 560 万美元 (DeepSeek-AI 2024)。这个数字得注意，但报告很小心地说了不包括什么：前期研究、架构和数据消融、所有不在最后这一次训练里的东西。对自建决策的启示是这样的：公开的训练数字只是冰山一角，找出配方的研究工作藏在下面，根本不会出现在那一次训练的账单上。

争议所在推理是否主导全生命周期账单还在打嘴仗，不是板上钉钉的事。标准论点很有说服力：训练一次性花，推理在模型整个服役期间持续付钱，对被广泛用的模型来说，运营成本会把训练成本远远甩在后头 [@sardana2024beyond]。可是推理模型和测试时扩展，也就是 @sec-inference-time-scaling 要讲的，从推理这边把问题搞复杂了。一个请求如果要跑很长的内部推理链，成本可能比直接回答高好几个数量级，这把单次请求成本推高不少，把总支出的更大一块又推回推理那边，不是训练。到底多次便宜调用还是少数昂贵调用成了瓶颈，现在还说不清，取决于具体产品。不要把这个比例当通用公式，而要把它当作某个具体部署可以测量的一个特性。
约束箭头

第 3 章 已经指出了一条从服务成本向上指向模型大小选择的箭头：推理量足够大时，应该把一个较小的模型过度训练到超过 Chinchilla 最优点 (Hoffmann et al. 2022; Sardana et al. 2024)。经济学在这儿闭合了第二条箭头，反向的。被服务词元的单位成本由加速器市场价格除以服务栈吞吐量决定，这个数决定了自建和购买的损益平衡。用量在这个点下面，下跌的 API 价格胜出，你买；用量在这个点上面，你付给 API 厂商的单价超过你自己的边际成本，你自建。一个工作负载落在这条线的哪一侧，由这个推理等式本身决定，不是策略选择。

拐点在哪里

每个经济选择都有个拐点，过了那个点另一个选项就更便宜了。

  • 资本成本还是运营成本。 按 第 3 章 的思路，把一个较小的模型过度训练到超过 Chinchilla 最优，训练上多花钱，但能把未来每一笔推理成本都压下来 (Sardana et al. 2024)。这种权衡只在全生命周期词元量足够大、能摊销那笔额外训练时才划算，取决于你必须在真正有用量之前就做的用量预测。
  • 自建还是购买。 通过 API 购买把资本成本转成按词元的运营成本，还能搭上价格下跌的列车，代价是数据、延迟、定制都不由你说了算。自建又变成资本成本加一笔固定的服务开销，只有用量特别大或有非价格约束时才值得。
  • 预留还是 spot。 预留容量便宜点、可预测，适合稳定生产。Spot 更便宜但随时可能被赶出来，适合可以中断的活儿：批量推理、有检查点的训练、超参数扫描。把工作负载能不能中断和对应价格档匹配好，才是节支的关键。
  • 质量还是单价。 更大或更重推理的模型答得更好，但每次请求也贵。经济上最合适的，是刚好过得了质量门槛的最小模型，这就是为什么把工作负载按模型大小分流，往往比全部丢给最大的那个好。

算这两个数

经济学要落地成操作，团队得真正算的是两个小数字，每个时钟一个。

第一个是上面那个推理单位成本公式。变成实际数字需要三样东西：算力市场的加速器时价、服务栈测得的实际吞吐量（词元/小时），还有实现的利用率。同一个等式也解释了第六部分每项优化为什么都能自己赚回成本：吞吐或利用率翻倍，单词元成本就砍半，单词元成本是下游所有利润的基数。

第二个是自建和购买的损益平衡。设 ppp 是每词元的 API 价格，ccc 是你用上面公式算出来的单词元边际成本，FFF 是搭建和维持你服务容量的固定成本。购买用量 VVV 要花 p×Vp \times Vp×V，自建要花 F+c×VF + c \times VF+c×V。自建在下面情况下才划算：

V>Fp−cV > \frac{F}{p - c} V>p−cF​

这个阈值作为正数存在，前提是你的边际成本 ccc 低于 API 价格 ppp。损益平衡点会随时间对你不利地漂移，因为 ppp 随市场下跌，所以今天算过的自建方案，必须在花资本前，用明年更低的 API 价格再检查一遍。

试试改下面的年下跌率或固定成本，看 API 价格逼近你边际成本时，损益平衡的用量怎么往上窜。

import numpy as np

F = 2_000_000.0   # fixed cost to stand up and reserve serving ($)
c = 0.20          # your marginal cost per million tokens ($)
p0 = 2.00         # API price per million tokens today ($)
decline = 0.40    # fraction the API price falls each year

for year in range(4):
    p = p0 * (1 - decline) ** year
    if p > c:
        breakeven = F / (p - c)   # millions of tokens to justify building
        print(f"year {year}: p=${p:5.2f}/Mtok  break-even = {breakeven:,.0f} Mtok")
    else:
        print(f"year {year}: p=${p:5.2f}/Mtok  build never pays (p <= c)")

完整的决策不是一个不等式，而是一条短的分支路径，图 37.2 把这个过程画出来了：有非价格约束直接自建，没有的话用量的阈值说了算，而 ppp 不断下跌会在你花资本前逼着重新算。

失败是经济上的，不是数学上的。对着下跌的 API 价格自建是经典失败：今年按 API 价格论证过的自托管方案，明年可能就赔了，但资本已经花了。为了应付尖峰就长期预留容量，波谷全浪费了；反过来用纯按需或 spot 应付尖峰，要么高峰付溢价，要么被踢下来。还有训练时对推理量估低了，一个实际用量远超预期的模型就训练不足，永久留下一笔任何服务优化都补不了的单词元成本。
