AI 的经济学

作者
Changkun Ou
更新于
2026 年 6 月 21 日
阅读时长
约 10 分钟

整个技术栈说到底是一种花钱的方式，而这笔账有它的形状。算力在哪里购买，训练与推理为什么是两种性质不同的成本，什么时候该自建一个模型、什么时候该通过 API 买一个，以及为什么「推理主导全生命周期账单」这个论断会反向上溯，影响 第 4 章 里的架构与扩展选择，这些就是本章要讲清的事。

发票有它的形状

前面各章的每一个决策，最终都落成一张发票上的某个数字。参数量是一笔训练账单。一种注意力变体意味着一份 KV 缓存，也就是按小时租来的内存。采样预算是服务账本上的一列。本章负责的，正是读者一直能感觉到、却还没点名的问题：既然算力是稀缺的输入，它如何定价，价格如何在「造一个模型」和「跑一个模型」之间切分，而这种切分又如何反过来影响该造什么。

有三个约束让这个问题变难，本章其余部分依次回答每一个。算力是在一个价格波动的市场里租来的，所以一次 FLOP 的成本是个移动的目标，不是常数。训练只付一次，推理要永远付，于是两种成本按不同的时钟增长。而最便宜的答案往往是从别人那里买能力，这意味着自建的决策要去和一个无从掌控、还在下跌的市场价格竞争。所以这张发票的形状由三件事决定：两种成本结构各按自己的时钟增长，二者之间张开一道缺口，而一个盈亏平衡点决定该买还是该造。

两种成本结构，各按各的时钟增长

统领全局的事实是：一个 AI 系统有两种成本结构，而不是一种，二者的行为差别大到，把它们混为一谈就会做出错误决策。

训练是一笔资本性支出。它规模大、批量化，而且在任何价值返回之前就已付出：占用集群数周，花掉一笔固定的钱，换来一组权重。这笔开销主要来自最终那一次训练，再加上找出配方的研究与消融训练。Epoch AI 分析了约 45 个前沿模型，发现最终训练那一次的摊销硬件与能源成本自 2016 年以来每年增长约 2.4 倍，其中硬件占最大的单项份额，研发人员占相当的一份，能源只占很小的余量 (Cottier et al. 2024)。这些头部数字带有时间性、只指方向：GPT-4 约 4000 万美元，Gemini Ultra 约 3000 万美元，照这一趋势，最大的训练会在 2027 年前后跨过十亿美元 (Cottier et al. 2024)。

推理是一笔运营性支出。它每次请求很小，每调用一次模型就付一次，所以它随用量扩展，而不随训练预算扩展。它的单位成本，有一个好用的一阶模型：

cost per token≈accelerator $/hourthroughput (tokens/hour)×utilization\text{cost per token} \approx \frac{\text{accelerator } \$/\text{hour}} {\text{throughput (tokens/hour)} \times \text{utilization}} cost per token≈throughput (tokens/hour)×utilizationaccelerator $/hour​

它告诉我们推理成本有三个杠杆：加速器的租用价格、服务栈从它身上榨出的吞吐，以及硬件被占满的程度。透过这个等式来看，第六部分的每一章都是在进攻分母：第 19 章 用批处理提高利用率，第 20 章 与 第 21 章 提高吞吐，第 8 章 的注意力变体则收缩每词元的工作量。

两种成本结构会分解成不同的驱动项，图 45.1 把它们并排摆出来：训练落成最终训练各加项之和，推理则落成一个比值，它的分母正是第六部分每一项优化的目标。

分子由算力市场设定。加速器在各大超大规模云商，以及一层专业 GPU 云上按小时出租，有三个价格档：承诺费率最低的预留容量，为灵活性多付溢价的按需，以及用「会被抢占」换最深折扣的 spot。进入 2025 年并延续到 2026 年，一块 H100 的按需租金是每 GPU 小时低个位数美元，spot 上则便宜得多，此前各大厂商在 2025 年间的大幅降价缓解了供给紧张。方向性的事实比任何单一报价都重要：一次 FLOP 的价格随时间下降，而一份按去年价格写就的服务计划，它的悲观程度会以复利累积。

剪刀：训练上升，推理下降

两个时钟不只是走得快慢不同。它们朝相反方向奔跑，而它们张开的那道缺口，是本章里最有分量的经济转变：在本领域的历程中，自建还是购买，默认答案已经反转。

早期，能力只存在于少数几家实验室之内，自建是拿到前沿模型的唯一办法，购买根本不是选项。随着托管 API 成熟，购买成为可能，随后第二条曲线接管了局面：一个推理词元的价格每年下降超过一个数量级。同一种能力，2023 年 GPT-4 发布时每百万词元要花数十美元，几年后，同等质量只要一美元的一个小零头。强开放权重模型的发布，其中包括 DeepSeek-V3，给了每个闭源提供商一个可供对标的低价参照点，加速了这一过程，也在全市场触发了反复的公开降价 (DeepSeek-AI 2024)。

拖动衰减参数，看看每词元价格塌陷得有多快，这正是自建决策必须赛跑追赶的那把剪刀的下刃。

把两条曲线摆在一起，这把剪刀就一目了然。训练成本在前沿每年上升约 2.4 倍 (Cottier et al. 2024)，API 推理价格每年下降约一个数量级。二者之间不断张开的缺口，正是默认答案从自建漂向购买的原因。从零自建一个前沿模型，要去和一个正在脚下塌陷的市场价格竞争，所以自建只在某种市场买不到的东西利害攸关时才划算：不能离开自己边界的专有数据，API 满足不了的延迟或可用性下限，托管模型不肯接受的定制，或者大到自托管胜过按词元加价的推理量。

自建这笔账本身也变了。DeepSeek-V3 是一个 6710 亿参数的混合专家模型，报告里它最终训练约 278.8 万 H800 GPU 小时，按假设的每 GPU 小时两美元算，约合 560 万美元 (DeepSeek-AI 2024)。这个数字引人注目，而报告很谨慎地说明了它排除了什么：先前的研究、架构与数据的消融，以及一切不属于那一次最终训练的东西。对自建决策的教训是：头部训练数字只是露出水面的尖端，找出配方的研究是水下的成本，它不会出现在那一次训练的发票上。

争议所在

推理是否主导全生命周期账单，是活跃的争论，而非已成定论的事实。标准论证很有力：训练只付一次，推理则在模型整个部署生命里按请求一次次付，对一个被广泛服务的模型，运营性支出会以很大的差距盖过资本性支出 (Sardana et al. 2024)。但推理模型和测试时算力，也就是 第 16 章 的主题，从推理这一侧把这个平衡搅复杂了，并没有把它解决。一次请求若花掉很长的内部思维链，成本可比一个直接答案高出数个数量级，这会剧烈抬升每请求成本，把总开销中更大的一块推回推理一侧，而不是训练一侧。主导成本究竟是许多次便宜调用，还是更少次昂贵调用，并无定论，且因产品而异。把这个切分当作某个具体部署的可测量属性，而不是一个普适的比值。

约束箭头

第 4 章 已经点出过一条从服务成本向上、伸进模型规模选择的箭头：高的全生命周期推理量，足以证明应当把一个更小的模型过度训练到超过 Chinchilla 最优点 (Hoffmann et al. 2022; Sardana et al. 2024)。经济学在这里闭合了第二条朝相反方向走的箭头。一个被服务词元的单位成本，由加速器的市场价格除以服务栈的吞吐设定，正是它定下了自建与购买决策里的盈亏平衡量。低于这个量，下跌的 API 价格胜出，于是买；高于这个量，付给提供商的按词元加价超过自己的边际成本，于是造。决定一个工作负载落在线哪一侧的，是推理等式，而不是某种策略偏好。

拐点在哪里

每个经济选择都是一个带拐点的平衡，越过那个点，更便宜的选项就翻了过来。

  • 资本性成本还是运营性成本。 在 第 4 章 的意义上，把一个更小的模型过度训练到超过 Chinchilla 最优点，从而在训练上多花钱，会压低未来每一笔推理账单 (Sardana et al. 2024)。这笔交换只有在全生命周期词元量大到足以摊销那笔额外训练开销时才划算，所以正确的点取决于一个用量预测，而这个预测得在还没有用量的时候就做出来。
  • 自建还是购买。 通过 API 购买，把一笔资本性支出转成按词元的运营性支出，搭上下跌的市场价格，代价是交出对数据、延迟和定制的掌控。自建把它转回资本性支出，再加一份固定的服务占用，只有越过某个盈亏平衡量、或某个非价格约束逼到头上时才胜出。
  • 预留容量还是 spot 容量。 预留算力每小时更便宜、也可预测，适合稳定的生产服务。spot 还要更便宜，但可能被抢占，适合可中断的工作：批量推理、带检查点的训练、超参数扫描。把工作负载的中断容忍度对准定价档，就是大部分节省的来源。
  • 质量还是单位成本。 一个更大、或更重推理的模型，答得更好，每请求也更贵。经济上正确的模型，是那个能越过任务质量门槛的最小模型，这也是为什么把一个工作负载在一梯模型规模之间做路由，往往胜过把一切都丢给最大的那个。

算这两个数

经济学要落到操作上，靠的是团队真正会去算的两个小计算，每个时钟一个。

第一个是上面那个推理单位成本。要把它变成一个数字，需要算力市场给的加速器小时价格、服务栈以每小时词元计的实测吞吐，以及实际达到的利用率。同一个等式也解释了第六部分的优化为什么能直接回本：吞吐或利用率翻倍，每词元成本就减半，而每词元成本正是下游每一笔利润据以计算的基准。

第二个是自建与购买的盈亏平衡。设 ppp 为每词元的 API 价格，ccc 为来自上面等式的每词元自有边际成本，FFF 为搭建并预留自有服务容量的固定成本。买，在用量 VVV 上花 p×Vp \times Vp×V；造，花 F+c×VF + c \times VF+c×V。当下面这个条件成立后，自建胜出

V>Fp−cV > \frac{F}{p - c} V>p−cF​

只有当边际成本 ccc 低于 API 价格 ppp 时，这个正阈值才存在。盈亏平衡点会随时间朝不利的方向移动，因为 ppp 随市场下降，所以一笔今天算得过来的自建，必须在投入资本之前，对照明年更低的 API 价格重新核算一遍。

试着改一改下面的年降价比例或固定成本，看着 API 价格朝边际成本靠近时，盈亏平衡量怎样一路攀升。

import numpy as np

F = 2_000_000.0   # fixed cost to stand up and reserve serving ($)
c = 0.20          # your marginal cost per million tokens ($)
p0 = 2.00         # API price per million tokens today ($)
decline = 0.40    # fraction the API price falls each year

for year in range(4):
    p = p0 * (1 - decline) ** year
    if p > c:
        breakeven = F / (p - c)   # millions of tokens to justify building
        print(f"year {year}: p=${p:5.2f}/Mtok  break-even = {breakeven:,.0f} Mtok")
    else:
        print(f"year {year}: p=${p:5.2f}/Mtok  build never pays (p <= c)")

完整的决策不是一个不等式，而是一条短的分支路径，画在 图 45.2 里：一个非价格约束直接短路到自建，其余的由用量阈值决定，而下跌的 ppp 会在任何资本花出之前，强制一次重新核算。

失效模式是经济性的，不是数值性的。对着下跌的购买价格去自建，是最经典的一种：一个按今年 API 价格论证得通的自托管计划，一年后可能已经亏本，而资本早就花出去了。为尖峰需求长期配置预留容量，会浪费掉波谷；用纯按需或 spot 去服务尖峰需求，则要么在波峰付溢价，要么冒被抢占的风险。而在训练时把推理量预测得过低，会让一个将被服务得远超预期的模型训练不足，留下一笔永久的每词元成本搁在桌上，任何服务优化都无法完全把它挽回。
