选择模型

作者
Changkun Ou
更新于
2026 年 6 月 21 日
阅读时长
约 11 分钟

任何技术栈里，第一个落地的决定就是调用哪个模型。它看起来像个质量问题，其实多半不是。把一个模型放到从闭源到开源的坐标轴上，读懂它的许可证究竟允许什么，在三个排行榜之间交叉验证而不被任何单一榜单误导，跑一套小规模评测来真正拍板，再把结果固定下来、接入技术栈，让某个厂商每周一次的小版本更新无法悄悄改变你的产品，这些就是落地选型要逐一过手的环节。本章是 第 40 章 的动手版伴读，那一章勾勒了开放性这条坐标轴；也是 第 28 章 的伴读，那一章说明了为什么一个公布出来的分数，是关于「模型加测量框架」二者合一的论断。

带日期的快照：引用前先核实

下文每一个模型名称、价格、上下文长度和排名，都是 2026 年年中（2026-06-20） 的快照，并尽可能标注了一手来源。版本每周都在发布，价格在变，排名在相互重叠的置信区间内轮换。请把这里每一个具体数字，都当作一个需要对照所链接一手文档来确认的假设，绝不要当成永恒事实。真正耐久的内容，是这些类别、权衡，以及决策与接线的流程。读这些来学方法；投入预算之前，重新核对数字。

主坐标轴：租用还是自有

有一条坐标轴几乎能预测模型选择的其余一切，而它不是质量。它问的是：你究竟是在一个计量计费的 API 后面租用能力，还是自有权重、自己运行。

前沿托管模型是某个实验室愿意暴露出来的最强通用模型，部署在按 token 计费的 API 后面。你发送 token，他们计费，你从不持有权重。实验室拥有整个服务栈：批处理、KV 缓存、推测解码、自动扩缩容和加速器（第 44 章）。你继承他们的延迟分布和速率上限，并把这些服务侧优化当作旋钮来消费（缓存输入定价、批处理与优先级档位），而不是亲自运维它们。

开放权重模型则是那种你可以下载训练好的参数、在自己硬件上运行的模型。你承担运维负担，作为交换，你掌控成本、延迟、数据驻留，以及微调的权利。你选的模型家族决定了你的推理服务器（vLLM、SGLang、llama.cpp；见 第 44 章）必须加载什么、需要多少显存、能达到多大吞吐。

这正是全书反复描绘的那个取舍：租用能力，交出服务栈的掌控权；或者自托管权重，自担运维。到了 2026 年，那道曾让此事成为质量妥协的差距，已大体闭合。最好的开放权重，如今在编码与推理榜单上已逼近闭源前沿模型一两个百分点，这就把「自托管还是调 API」从一种让步，变成了一个真正的架构决策（据 Artificial Analysis 与各开源 LLM 排行榜，截至 2026-06）。

先读许可证，再读基准

对开放权重而言，许可证比基准更能拍板，因为无论分数多高，一份许可证都可能让某个模型在你的产品里直接出局。三个层级很要紧。

  • 真正开放（Apache-2.0、MIT）。 没有用户上限，没有使用领域限制，没有地域排除条款。截至 2026 年年中，Qwen、DeepSeek、Mistral 当前旗舰、Gemma 4、gpt-oss、GLM 和 OLMo 都在这一档。当你可能扩张到几千万用户以上、在欧盟运营、或者想要零使用领域歧义时，选这一档。
  • 源可得（受限）。 权重可下载，但许可证附加了上限或排除条款。Meta 的 Llama 4 Community License 仅在 7 亿月活以下允许商用，并且对欧盟境内被许可方排除多模态功能，之上还有一份可接受使用政策。这不是 OSI 意义上的开放。在它上面构建之前，先去读真正的 LICENSE。
  • 闭源（无权重）。 托管 API 前沿。你拿到的是一份合同和一个端点，不是参数。

第二条、与之正交的区分是开放权重对完全开放。多数「开放」模型只发布权重；训练数据和完整配方仍是私有的。一小部分（AI2 的 OLMo）连数据、代码和检查点也一并发布。如果你需要可复现、可审计，或从零重训的能力，这个差别就是全部关键，而它与许可证档级互相独立。

耐久的规则是：对任何可能扩张、或要在受监管地区上线的东西，先读许可证，再读排行榜。

约束箭头：服务成本向上影响模型选择

对开放权重而言，下层的服务层决定上层的模型。Mixture-of-Experts 模型让你以近稠密的推理成本，换取更高的质量上限，但总参数仍必须装进显存，所以一个 1.6T/49B 的模型即便每 token 只激活 49B，也是集群模型。一个 31B 的稠密模型，可能比 122B-A10B 的 MoE 更易服务、更易量化（第 19 章），尽管激活算力相近。先收窄你候选清单的，是你手上的硬件，而不是基准。

读排行榜而不被骗

排行榜是一个收窄候选的工具，不是裁决。第 28 章 给出的最重要的实务教训是：一个公布出来的分数，是关于「模型加测量框架」二者合一的论断，而不是关于模型本身。 对同一份权重做独立重跑，会因提示模板、系统提示、工具脚手架、采样参数和评分器的不同，而摆动 10 到 20 个百分点。2026 年反复出现的模式是：一个模型在公开、可验证的编码榜上的分数，明显高于同一份权重在留出框架上的分数，而那道差距是框架加上可能的污染，而非模型本身的变化。

所以要读三个榜，而不是一个，并把榜单对准你真正在问的问题。

你在问的问题 该读的榜 它无法告诉你的
「在开放式对话里用户更喜欢哪个？」 LMArena / arena.ai（人类偏好 Elo） 正确性。偏好奖励自信、更长、排版更好的回答；高 Elo 配错误答案是真实存在的失败模式。
「在我的延迟下每美元最佳智能？」 Artificial Analysis（智能指数，标准化框架，含成本与 tokens/秒轴） 那套标准化框架是否匹配你的提示、工具与采样。
「一个高的公开分是否虚高？」 抗污染榜：FrontierMath、LiveCodeBench、Epoch、Scale SEAL 覆盖广度；这些更新更慢、覆盖任务更少。
「它能跑我的智能体吗？」 可验证的智能体榜：SWE-bench Verified、Terminal-Bench、τ-bench、Aider polyglot、BFCL 单轮知识质量；这些考验的是脚手架（第 30 章）。
「新版本是否退化了？」 已饱和的旧榜（MMLU、HumanEval）仅作下限 前沿排名；榜首集群在这里只是噪声。

三个榜一致是强信号。不一致则恰好告诉你哪一条轴脆弱。污染的征兆是：一个模型公开集分数与其留出或截止后分数之间的大差距。小差距是可信信号，大差距是危险信号。

何处存争议：最佳、可用、被允许是不同的轴

2026 年年中，文本榜首集群落在相互重叠的置信区间里，且每周轮换，所以任何单一的「第一」论断都是一个档位，不是赢家。更糟的是，排名是必要而非充分条件。最典型的提醒：Anthropic 的 Fable 5 与 Mythos 5 在发布时（2026-06-09）登顶多个榜单，而接入在 2026-06-12 被暂停，遵从一项美国出口管制指令（CNBC、Al Jazeera、Fortune、Anthropic）。一个登顶的模型，可能被出口管制、被区域锁定、被限速，或超出你的预算。要在对你可用、且你的政策允许的模型里挑选，再在该集合内排名。不要把默认押在一个你无法可靠调用的模型上。

一套决策框架

这个决策很少是「哪个分最高」。它是你在哪里被计费、任务的形态、上下文对成本、治理，以及（对开放权重）你手上的硬件这几者的交集。图 43.1 走一遍这些因素真正拍板的顺序。

把它写成经验法则，大致按拍板顺序：

  • 先按你住在哪里挑。 你被计费所在的云，通常在采购、数据驻留和承诺用量折扣上胜出。重度 AWS 用户走 Bedrock；Azure 走 Azure OpenAI；GCP 走 Vertex AI。
  • 当工作负载是智能体编码、长程工具使用，或安全敏感，且你看重可靠性和固定、可复现的模型 ID 时，选 Claude（Opus 4.8 / Sonnet 4.6）。
  • 当你想要最宽的生态与工具，或你在 Azure 上时，选 GPT-5.5。
  • 当你在 GCP 上，或输入确实是多模态（一个模型里有音频、视频、PDF）时，选 Gemini 3.1 Pro。
  • 当每 token 价格和超长上下文占主导、且治理允许时，选 Grok 或 DeepSeek。
  • 当你必须掌控成本、延迟、驻留或微调权利（第 45 章）、且你有硬件时，选一个开放家族（默认 Qwen3.5/3.6）。前沿智能体编码选 DeepSeek-V4，单 GPU 选 Gemma 4，可复现是硬要求时选 OLMo 3。

长上下文值得单独提醒。它昂贵：OpenAI 对超过约 272K 的提示按溢价计费，Gemini 对超过 200K 的输入价格大致翻倍。能用检索就别硬塞窗口（第 47 章）；这通常比依赖裸上下文长度更便宜、更可靠。

在代码里拨动滑块试试：改变阈值和越过悬崖后的倍率，看看在哪一点上，硬塞整个窗口不再划算，而检索一个固定的小切片更划算。

import numpy as np
import matplotlib.pyplot as plt
base = 2.0 / 1e6           # $ per input token below the cliff
threshold = 200_000        # tokens; price kink here
mult = 2.0                 # over-cliff tokens cost this much more (marginal)
retrieved = 8_000          # fixed small window when you retrieve instead
n = np.linspace(0, 600_000, 400)
over = np.maximum(n - threshold, 0)
stuff = base * (np.minimum(n, threshold) + over * mult)  # tiered, not flat
retrieve = np.full_like(n, base * retrieved)             # retrieval is flat
plt.plot(n / 1e3, stuff, label="stuff the window")
plt.plot(n / 1e3, retrieve, "--", label=f"retrieve {retrieved // 1000}K")
plt.axvline(threshold / 1e3, color="gray", ls=":", label="price cliff")
plt.xlabel("relevant tokens (thousands)"); plt.ylabel("cost per call ($)")
plt.legend(); plt.title("Long-context cliff vs retrieval"); plt.show()
print(f"At 400K tokens: stuff=${base*(threshold+200_000*mult):.3f}, "
      f"retrieve=${base*retrieved:.3f}")

一个合理的默认，以及为什么

截至 2026 年年中，对一支构建智能体与 RAG 功能、且未锁定特定云的典型产品团队：

  • 托管默认：Anthropic Claude。 Sonnet 4.6 作日常主力，遇到最难的智能体与编码步骤再升级到 Opus 4.8。两者都已普遍可用，带固定模型 ID、1M 上下文，并在四大接入层上都有过硬的智能体编码记录。注意上文争议框里的协调结论：不要因为 Fable 5 或 Mythos 5 登顶就把它们设为默认，因为接入在 2026-06-12 被暂停。榜上最佳，不等于可以调用。
  • 强力备选： GPT-5.5 用于最宽生态或 Azure；Gemini 3.1 Pro 用于 GCP 或多模态。
  • 自托管默认：Qwen3.5/3.6 家族（Apache-2.0），2026 年最全面的真正开放谱系，前沿智能体编码配 DeepSeek-V4，单 GPU 配 Gemma 4，需要完整可复现时配 OLMo 3。

不要把单一厂商写死。在前面放一个网关，让你能按任务路由和故障切换，并每季度重估默认；前几名之间的差距很小，版本不断更替。这个默认是一个起步姿态，不是裁决。裁决是你自己的评测。

固定并评测：真正拍板的那一步

公开榜把候选收窄到三四个。只有你自己的离线评测能挑出赢家，因为只有你的评测匹配你的分布、你的提示、你的工具和你的验收门槛。

两条纪律让这件事落地。把每个模型 ID 固定到配置里的一个快照，绝不用「latest」，这样厂商的小版本就无法悄悄改变行为。把你的评测集当作仓库里一份带版本的契约，像测试套件一样：换模型是对它的一个 diff，改提示是对它的一个 diff，CI 在任何升级前先跑它。用真实流量构建它（50 到 200 条就够起步），尽量用可验证的评分器打分（精确匹配、单元测试），只在不得已时才用 LLM 裁判（第 29 章），并始终把成本和延迟与准确率并列报告，绝不只报准确率。被记录的生产失败，成为下个季度的评测条目。

# eval.yaml  (versioned in-repo; CI gate on every model or prompt change)
dataset: ./evals/support_v7.jsonl    # private, from real traffic, versioned
candidates:                          # shortlist from the public boards
  - anthropic/claude-opus-4-8        # pinned snapshot IDs, never "latest"
  - openai/gpt-5.5
  - google/gemini-3.1-pro
graders:
  - type: exact_match                # verifiable wherever possible
  - type: unit_test                  # for code-shaped outputs
  - type: llm_judge                  # sparingly; pin the judge + rubric version
    judge_model: pinned-strong-model
    rubric: ./evals/rubric_v3.md
report:
  axes: [accuracy, cost_per_task, p95_latency]   # never accuracy alone
  ci: bootstrap_95                   # report intervals; a single number lies
gate:
  block_merge_if: accuracy_drop > 2pct OR p95_latency_regression > 15pct

接入技术栈

应用永远不该直接对接厂商的原始 SDK。它对接一个网关，由网关持有密钥、强制每个团队的预算与速率上限、归一化请求形态，并在提供方之间故障切换（第 49 章）。对闭源 API，没有你要运维的服务层，所以网关就是你的控制点；对开放权重，网关坐在你自己的推理服务器前面，而后者暴露同一套 OpenAI 兼容 API，所以智能体代码在两者之间无需改动。图 43.2 展示了这个接缝。

一份与提供方无关的路由配置，把按任务的选择和回退链写明白，并守住长上下文的价格悬崖：

# gateway routing (illustrative; every model is a pinned snapshot ID)
default_model: anthropic/claude-sonnet-4-6
routes:
  - match: { task: hard_coding }      # escalate the gnarly agentic steps
    model: anthropic/claude-opus-4-8
  - match: { task: multimodal }       # audio / video / pdf in one model
    model: google/gemini-3.1-pro
  - match: { task: bulk_cheap }       # high-volume, cost-capped
    model: deepseek/deepseek-v3.2
fallbacks:
  anthropic/claude-opus-4-8: [openai/gpt-5.5, google/gemini-3.1-pro]
limits:
  long_context_guard: 200000          # warn before the >200K price cliff

能力、效率、信任这个透镜为本章收尾。能力是排行榜衡量、你的评测确认的东西。效率是每任务成本与延迟，这就是为什么任何排名离开了旁边的价格与速度轴，都毫无意义。信任是许可证、治理姿态和可用性保证：Fable 5 的暂停提醒我们，一个你无法可靠且合法调用的模型，对你而言根本没有能力。在三者上一并挑选，固定结果，让你的评测、而非排行榜，投下拍板的一票。
