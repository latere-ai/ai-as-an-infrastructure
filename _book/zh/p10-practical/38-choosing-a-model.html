第十部分 · 实践：搭建 2026 技术栈 · 第 38 章

选择模型

任何技术栈的第一步决定，就是选哪个模型来调用。这看起来像个质量问题，实际上大多数时候根本不是。你需要把模型摆在闭源到开源这条轴上，看清许可证真正允许什么，在几个排行榜间交叉验证而不被其中任何一个带偏，跑一套快速评测来真正拍板，最后把选择固定下来、集成进栈里，这样厂商每周的小版本更新就改不了你的产品行为。第 35 章 从开放性这条轴线铺起基础；第 27 章 解释了为什么一个公开的分数是关于「模型加测量框架」这个整体的宣称。这一章是把那些理论付诸实操。

带日期的快照：引用前先核实

下文每一个模型名称、价格、上下文长度和排名，都是 2026 年年中（2026-06-20） 的快照，并尽可能标注了一手来源。版本每周都在发布，价格在变，排名在相互重叠的置信区间内轮换。请把这里每一个具体数字都当作一个需要去对照所链接一手文档来确认的假设，绝不要当成永恒事实。真正耐久的内容是这些类别、权衡，以及决策与接线的流程。读这些来学方法；在投入预算前重新核对数字。

主坐标轴：租用还是自有

有一条坐标轴几乎能预测其他一切，但它不是质量。就是你到底是在计量 API 后面租用能力，还是自己拿下权重自己跑。

前沿托管模型是某个实验室肯放出去的最强通用模型，部署在按 token 计费的 API 后面。你送 token，他们计费，权重你从没见过。服务栈是他们的：批处理、KV 缓存、推测解码、自动扩缩容、加速器（第 39 章），全由他们操持。你继承他们的延迟分布和速率限制，把那些服务侧优化当作旋钮来用（缓存输入定价、优先级档位），而不用自己装。

开放权重模型是权重你能下载、在自己硬件上跑的那种。你得自己维护，作为代价，你掌控成本、延迟、数据驻留和微调权。选了哪个模型家族，推理服务器（vLLM、SGLang、llama.cpp；第 39 章）得加载什么、显存吃多少、能推出多少吞吐，全由它决定。

这就是全书讲了多次的权衡：租能力、放弃服务栈的掌控；或自托主权重、自己担运维。到 2026 年，过去让人在质量和自主间二选一的那道鸿沟基本闭合了。最好的开放权重如今在编码和推理板上已追到闭源前沿一两个百分点以内，「自托管还是调 API」从妥协变成了真实的架构选择（据 Artificial Analysis 和各开源 LLM 榜单，截至 2026-06）。

先读许可证，再读基准

对开放权重来说，许可证比基准更能定局，因为再高的分数也挡不住一份许可证把某个模型挡在门外。三个档级值得留意。

  • 真正开放（Apache-2.0、MIT）。 无用户上限，无使用领域限制，无地域排除。到 2026 年年中，Qwen、DeepSeek、Mistral 当前旗舰、Gemma 4、gpt-oss、GLM 和 OLMo 都归这档。如果你可能涨到数千万用户、在欧盟运营，或就是想要零使用领域歧义，选这档。
  • 源可得（受限）。 权重能下，但许可证加了上限或排除。Meta 的 Llama 4 Community License 只在月活 7 亿以下允许商用，还要对欧盟被许可方排除多模态，上面还叠一份可接受使用政策。这不是 OSI 开放的意思。在它上面搭东西前，去读真正的 LICENSE。
  • 闭源（无权重）。 托管 API 前沿。拿到的是合同和端点，不是参数。

第二条、正交的区分是开放权重对阵完全开放。多数「开放」模型只放权重；训练数据和完整方子还是藏着。少数（AI2 的 OLMo）连数据、代码、检查点全放。需要可复现、可审计或从头重训的能力，这个差别就是全部游戏，而且它与许可档级正交。

经验规则：任何可能扩张、要在受监管地区上线的东西，许可证先于排行榜。

约束箭头：服务成本向上影响模型选择

对开放权重来说，下层服务决定上层模型。Mixture-of-Experts 给你近稠密的推理成本但换更高的质量天花板，可总参数还是要装进显存，1.6T/49B 即便每 token 激活 49B，也得是集群规模。31B 稠密模型可能比 122B-A10B MoE 更好服、更好量化（第 19 章），尽管激活算力差不多。先甄选候选清单的，是你的硬件，不是基准。

读排行榜而不被骗

排行榜是收窄候选的工具，不是裁决。第 27 章 讲的最要紧的一课是：一个公开的分数是关于「模型加测量框架」这个整体的宣称，不是关于模型单独的。 同一份权重独立重跑，会因提示模板、系统提示、工具脚手架、采样和评分器不同而摆动 10 到 20 个百分点。2026 年反复的现象是：一个模型在公开可验证的编码板上的分数，明显高于同一份权重在留出集上的分数，那差距是框架加可能的数据污染，不是模型本身变了。

所以要看三个榜，不是一个，并且榜单要对准你真正问的问题。

你在问的问题 该读的榜 它无法告诉你的
"在开放式对话里用户更喜欢哪个？" LMArena / arena.ai（人类偏好 Elo） 正确性。偏好奖励自信、更长、排版更好的回答；高 Elo 配错误答案是真实存在的失败模式。
"在我的延迟下每美元最佳智能？" Artificial Analysis（智能指数，标准化框架，含成本与 tokens/秒轴） 那套标准化框架是否匹配你的提示、工具与采样。
"一个高的公开分是否虚高？" 抗污染榜：FrontierMath、LiveCodeBench、Epoch、Scale SEAL 覆盖广度；这些更新更慢、覆盖任务更少。
"它能跑我的智能体吗？" 可验证的智能体榜：SWE-bench Verified、Terminal-Bench、τ-bench、Aider polyglot、BFCL 单轮知识质量；这些考验的是脚手架（第 29 章）。
"新版本是否退化了？" 已饱和的旧榜（MMLU、HumanEval）仅作下限 前沿排名；榜首集群在这里只是噪声。

三榜一致是强信号。不一致则恰恰说明哪条轴脆弱。污染的迹象是：一个模型公开集分数和它的留出/截止后分数间有大差距。小差距是信号好，大差距是信号坏。

何处存争议：最佳、可用、被允许是不同的轴

2026 年年中，文本榜首集群落在相互重叠的置信区间里且每周轮换，所以单一「第一」论断都是一个档位，不是赢家。更糟是排名必要但不充分。最好的提醒是 Anthropic 的 Fable 5 和 Mythos 5：发布时（2026-06-09）登顶好几个榜，接入在 2026-06-12 被暂停，遵从美国出口管制指令（CNBC、Al Jazeera、Fortune、Anthropic）。一个登顶的模型可能被出口管制、被区域锁、被限速，或贵得用不起。要在对你可用且政策允许的模型里挑，再在那个集合内排名。别把赌注押在一个你无法可靠调用的模型上。

经验法则，大概按拍板顺序：

  • 先按你被计费的地方挑。 你被计费的云通常在采购、数据驻留和承诺折扣上赢。重度 AWS 用户上 Bedrock；Azure 上 Azure OpenAI；GCP 上 Vertex。
  • 当工作是智能体编码、长程工具使用或安全敏感，且你要可靠性和固定可复现模型 ID，选 Claude（Opus 4.8 / Sonnet 4.6）。
  • 当你要最宽的生态或工具，或在 Azure，选 GPT-5.5。
  • 当你在 GCP，或输入真是多模态（一个模型里有音频、视频、PDF），选 Gemini 3.1 Pro。
  • 当每 token 价格和超长上下文主导、且治理允许，选 Grok 或 DeepSeek。
  • 当你必须控成本、延迟、驻留或微调权（第 40 章），且有硬件，选一个开放家族（默认 Qwen3.5/3.6）。前沿智能体编码选 DeepSeek-V4，单 GPU 选 Gemma 4，可复现硬要求选 OLMo 3。

长上下文要单说。它贵：OpenAI 对超过约 272K 的提示按溢价计，Gemini 超过 200K 输入价大约翻倍。能用检索就别硬塞窗口（第 42 章）；这通常比靠裸上下文长度便宜也更靠谱。

在代码里拨滑块试试：改阈值和悬崖倍率，看在哪一点，硬塞整个窗口不再划算，而检索一个固定小片段更划算。

import numpy as np
import matplotlib.pyplot as plt
base = 2.0 / 1e6           # $ per input token below the cliff
threshold = 200_000        # tokens; price kink here
mult = 2.0                 # over-cliff tokens cost this much more (marginal)
retrieved = 8_000          # fixed small window when you retrieve instead
n = np.linspace(0, 600_000, 400)
over = np.maximum(n - threshold, 0)
stuff = base * (np.minimum(n, threshold) + over * mult)  # tiered, not flat
retrieve = np.full_like(n, base * retrieved)             # retrieval is flat
plt.plot(n / 1e3, stuff, label="stuff the window")
plt.plot(n / 1e3, retrieve, "--", label=f"retrieve {retrieved // 1000}K")
plt.axvline(threshold / 1e3, color="gray", ls=":", label="price cliff")
plt.xlabel("relevant tokens (thousands)"); plt.ylabel("cost per call ($)")
plt.legend(); plt.title("Long-context cliff vs retrieval"); plt.show()
print(f"At 400K tokens: stuff=${base*(threshold+200_000*mult):.3f}, "
      f"retrieve=${base*retrieved:.3f}")

一个合理的默认，以及为什么

2026 年年中，对一支造智能体和 RAG 功能、不被特定云锁定的典型产品团队：

  • 托管默认：Anthropic Claude。 Sonnet 4.6 做日常主力，最难的智能体和编码步骤升级到 Opus 4.8。都已普遍可用，都有固定模型 ID、1M 上下文，在四大接入层都有坚实的智能体编码历史。注意上文争议框的结论：别因 Fable 5 或 Mythos 5 登顶就设成默认，因为接入 2026-06-12 被暂停了。榜首和能调不是一回事。
  • 强力备选： GPT-5.5 用最宽生态或 Azure；Gemini 3.1 Pro 用 GCP 或多模态。
  • 自托管默认：Qwen3.5/3.6 家族（Apache-2.0），2026 年最全面的真正开放选项，配 DeepSeek-V4 做前沿智能体编码，单 GPU 配 Gemma 4，要完整可复现时配 OLMo 3。

别把单个厂商写死。在前面放个网关，让你按任务路由和故障切换，每季度重估默认；前几名差距很小，版本不停更新。这个默认是起步姿态，不是裁决。裁决是你自己的评测。

固定并评测：真正拍板的那一步

公开榜把候选收到三四个。只有你的离线评测能挑赢家，因为只有你的评测才匹配你的分布、提示、工具和验收门槛。

两条纪律让它落地。把每个模型 ID 固定到配置的一个快照，绝不用 latest，这样厂商的小版本改不了行为。把评测集当成仓库里一份带版本的契约，像测试套件：换模型是对它的一个 diff，改提示是对它的一个 diff，任何升级前 CI 先跑它。用真实流量造（50 到 200 条起步够了），尽量用可验证的评分器（精确匹配、单元测试），只在必要时用 LLM 裁判（第 28 章），始终把成本和延迟与准确率并报，绝不单报准确率。被记的生产失败是下季度的评测条目。

# eval.yaml  (versioned in-repo; CI gate on every model or prompt change)
dataset: ./evals/support_v7.jsonl    # private, from real traffic, versioned
candidates:                          # shortlist from the public boards
  - anthropic/claude-opus-4-8        # pinned snapshot IDs, never "latest"
  - openai/gpt-5.5
  - google/gemini-3.1-pro
graders:
  - type: exact_match                # verifiable wherever possible
  - type: unit_test                  # for code-shaped outputs
  - type: llm_judge                  # sparingly; pin the judge + rubric version
    judge_model: pinned-strong-model
    rubric: ./evals/rubric_v3.md
report:
  axes: [accuracy, cost_per_task, p95_latency]   # never accuracy alone
  ci: bootstrap_95                   # report intervals; a single number lies
gate:
  block_merge_if: accuracy_drop > 2pct OR p95_latency_regression > 15pct

接入技术栈

应用不要直接对接厂商 SDK。要对接一个网关，网关持密钥、强制团队预算和速率上限、归一化请求，并在提供方间故障切换（第 44 章）。对闭源 API，没你要维护的服务层，网关就是你的控制点；对开放权重，网关坐在你的推理服务器前面，后者暴露同一套 OpenAI 兼容 API，智能体代码在两边无需改。图 38.2 展示这个接缝。

一份与提供方无关的路由配置，把按任务的选择和回退链写清楚，并守住长上下文价格悬崖：

# gateway routing (illustrative; every model is a pinned snapshot ID)
default_model: anthropic/claude-sonnet-4-6
routes:
  - match: { task: hard_coding }      # escalate the gnarly agentic steps
    model: anthropic/claude-opus-4-8
  - match: { task: multimodal }       # audio / video / pdf in one model
    model: google/gemini-3.1-pro
  - match: { task: bulk_cheap }       # high-volume, cost-capped
    model: deepseek/deepseek-v3.2
fallbacks:
  anthropic/claude-opus-4-8: [openai/gpt-5.5, google/gemini-3.1-pro]
limits:
  long_context_guard: 200000          # warn before the >200K price cliff

能力、效率、信任这三个透镜收尾。能力是榜单衡量、你的评测确认的东西。效率是每任务成本和延迟，这是为什么任何排名离开旁边的价格和速度轴都没意义。信任是许可、治理姿态和可用保证：Fable 5 暂停提醒我们，一个你无法可靠合法调用的模型对你根本没有能力。三者一起选，固定结果，让你的评测投一票，不是榜单。
